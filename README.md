# 拾音

使用 MyGo、Go、React 和 SQLite 的本地歌单播放器（macOS 为主要平台，也已适配并构建 Windows 版本）。界面以暖中性色为主、封面主导：浅色与深色两套主题共用一套结构，封面是屏幕上最响的部分；支持直接收藏与批量操作。`bili-music` 仅作为行为参考，未修改或迁移其数据。

## 使用

打开 `build/darwin-arm64/拾音.app`，或挂载 `build/darwin-arm64/shiyin-0.1.0-arm64.dmg`。

1. 输入关键词，选择视频或 UP 主搜索。进入 UP 主后，搜索会同时查找相关投稿和合集；也可切到「合集与系列」按名称筛选。投稿受限时仍可浏览可用的合集。
2. 首屏「探索声音」：从 B站音乐区排行榜随机抽 6 首，排成封面网格，可「换一批」；点封面直接试听（多 P 视频从第一 P 开始），封面上悬停出现「加入」按钮，可直接存进左侧选中的歌单。歌单都在左侧栏，首屏不重复列一遍。
3. 点击 UP 主或合集整行进入。合集可直接「全部加入」指定歌单，也可勾选歌曲后一次加入；读取期间可取消，取消不会写入部分歌曲。
4. 视频标题或播放按钮用于试听。普通浏览时点「加入」直接保存；多 P 视频可展开挑选。多选时，点击标题、封面或行内空白切换选择，不会直接播放；独立播放按钮仍可试听。视频父行选择全部分 P，部分选中显示半选，再点击补齐本组。
5. 切换页面保留已选歌曲，「返回」恢复上一级列表与滚动位置。「全选当前结果」只选择已加载结果，整合集导入会读取全部页面。
6. 歌单支持顺序、列表循环、单曲循环和随机播放，所选模式会在重开应用后恢复。可调整顺序、移除曲目并撤销移除，也可重命名或删除歌单。
7. 重开应用时播放器会回到上次选中的那首歌（暂停状态，按播放才开始取流），音量也会记住。摘下耳机（或断开蓝牙音箱）时播放会停在那首歌上，插回或不插都不自动续播——WebKit 自己不会这么做，是应用在监听系统的默认输出设备。左侧歌单名后的三根跳动条表示正在播放这张歌单；点击播放器左侧的封面和标题会回到它来自的地方——正在播歌单就打开那张歌单，试听就打开这个视频的搜索结果（能看到它的分 P 和合集）。
8. 左侧栏最下面的「设置」（或按 ⌘,）打开设置窗口，左侧分成四页：**外观**（跟随系统 / 浅色 / 深色、减弱动效）、**播放**（音量、启动时回到上次的歌曲）、**快捷键**、**关于**（图标、名称、版本、标识、资料库路径）。在「外观」里选「跟随系统」后，Mac 换外观这里也会跟着换。

快捷键在「设置 → 快捷键」里逐条修改：点一下右边的按键框，再按下新的组合即可；Esc 取消录制，已被别的动作占用的组合会提示是谁占着，⌘Q / ⌘W / ⌘H / ⌘M / ⌘Tab / ⌘Space 被系统或窗口先接走，不接受。「恢复默认」一键回到下表。默认值：

| 动作 | 默认快捷键 |
|---|---|
| 播放 / 暂停 | 空格（在输入框里打字时空格照常输入） |
| 上一首 / 下一首 | ⌥← / ⌥→ |
| 静音 / 取消静音 | ⇧⌘M |
| 聚焦搜索框 | ⌘F |
| 退出输入 / 清除筛选 | Esc |

点击关闭按钮或按 Cmd+W 后，窗口隐藏，音乐继续播放。点击菜单栏音符图标，选择「显示拾音」恢复窗口；选择「退出拾音」或按 Cmd+Q 才会停止播放并退出。

歌单保存到 `~/Library/Application Support/拾音/library.sqlite`。退出重开后仍保留。开发版和正式版共用此固定目录，不随可执行文件名、构建目录或版本变化；打包自动化测试使用独立临时目录。首次启动没有模拟歌曲。不下载歌曲、不登录账号、不同步 B站收藏；播放需要网络。视频只输出声音。

音乐区排行榜每 10 分钟最多取一次，取回后在本地打乱成牌堆；「换一批」从牌堆里发下一组，发完才重新请求，因此连续点击不会反复打 B站。

查询失败自动重试，每次查询最多请求 3 次（首次加 2 次重试），间隔 1 秒、2 秒。达到上限后暂停自动加载，保留已显示结果，可手动重新尝试。播放失败和歌单写入不自动重试。

## 当前限制：UP 主投稿接口风控

2026-10-27 本机访客实测：

- 视频搜索、UP 主搜索、视频分 P、合集列表、合集内容、独立音频地址解析通过。
- UP 主投稿 `/x/space/wbi/arc/search` 曾返回 HTTP 412／-352。补齐 yt-dlp 同类请求参数、空间页请求头和 `dm_*` 编码后，Aki惊蛰（UID 15319615）曾返回 HTTP 412。后续相同代码在使用／不使用环境代理的两组测试中均成功读取前两页（各 30 条）；重启新版原生应用后，首次请求 412，手动重试成功读取 30 条。当前属于间歇性失败，尚未验证账号登录态。
- 因此目前不能保证“搜索 UP 主后浏览其全部投稿”。界面保留该入口并明确报错；不会将错误显示为加载完毕，不会自动登录或替换为 UP 主关键词搜索。
- 目前可以使用全分区视频搜索，以及可访问的 UP 主合集/系列挑选歌曲。不同账号、视频、网络条件可能仍有访问限制。

播放失败只报错，保留歌曲。可手动重试或选择另一首。混合流会额外传输视频数据。只接受当前 WebView 支持的 MP4/AAC，不转码。

## 开发与构建

需要 Go 1.27.3+、Node.js 22.12+。本次安装的 Go 位于 `/Users/chen_wei/.local/share/mygo-music-toolchain/go/bin`；没有修改全局 PATH。

```sh
export PATH="/Users/chen_wei/.local/share/mygo-music-toolchain/go/bin:$PATH"
npm ci
go mod download
npm run dev
```

```sh
npm test
go test -race ./...
npm run build
```

修改界面后，已安装 App 不会随网页构建自动更新。请运行 `npm run build`，退出旧进程，再打开 `build/darwin-arm64/拾音.app`。

应用图标：源文件 `assets/icon.svg`（由 QuiverAI 生成，B站电视 + 音量条），界面里的品牌、「关于」和所有无封面的占位图都由 `src/logo.tsx` 复用同一份图稿。改图后运行 `./scripts/icon.sh`（需要 Xcode）：它按 macOS 的 824/1024 网格从 SVG 渲染 16→1024 各档并写成 `resources/Shiyin.icns`（`mygo.json` 的 `CFBundleIconFile` 指向它），渲染同网格的 1024px `assets/icon.png`（`mygo.json` 的 `icon`，Windows 会把它转成 exe 的 .ico，macOS 另外得到一份 AppIcon.icns），再从 `assets/tray.svg` 生成菜单栏用的 64px 单色模板 `assets/tray.png`；生成结果已提交，日常构建不需要重跑。

### 打包到 Windows

```sh
npx mygo build -platform windows/amd64
```

产出 `build/windows-amd64/拾音.exe`（PE32+ GUI，WebView2 外壳），交叉编译不需要 Windows 机器；exe 的图标、manifest 与版本信息由 mygo 从 `mygo.json` 的 `icon` 生成。安装包（NSIS）只在 Windows 上会自动下载 makensis，在 macOS 上要先 `brew install makensis`。

已经按平台分开的部分：库文件路径（macOS `~/Library/Application Support/拾音/`、Windows `%AppData%\拾音\`，「关于」显示的是各平台的写法）、快捷键标签（macOS `⇧⌘M`、`⌥←`；Windows `Ctrl+Shift+M`、`Ctrl+←`）与默认键位（Windows 的上一首/下一首用 `Ctrl+←/→`，避开 `Alt+←` 的前进后退）、摘耳机自动暂停（macOS 监听 CoreAudio，Windows 轮询默认播放端点）。

仍只在 macOS 上验证过的部分：`./scripts/smoke.sh` 与 `./scripts/icon.sh` 是 macOS 脚本；Windows 上尚未跑过打包后的界面与播放测试（WebView2 的自动播放策略尤其需要实测）；Linux 没有输出设备监听，也没有打包验证。

Go、MyGo 和 npm 依赖由 `go.mod`、`go.sum`、`package-lock.json` 固定。`npm run generate` 根据 Go 服务生成 `src/mygo.ts`，不要手改。`npm run dev:web` 只提供网页开发服务器，浏览器没有 MyGo IPC，不能作为可用播放器。

## 验证

- 前端 TypeScript 检查、Vite 构建、15 个前端测试通过，覆盖队列、整组选择、合集分页、搜索和取消。
- Go 测试与 race detector 通过：SQLite 重启/顺序/大 CID、重复收录、事务回滚、损坏或新版本数据库保护、Range 转发和流释放、过滤后的短搜索页仍保持正确分页。
- 使用独立临时资料库与受控媒体的打包 WKWebView 测试通过：真实 IPC、单 P 直接选择/取消及合集入口、空选曲篮隐藏、两分 P 内联保存、AAC 和混合 MP4 播放/暂停/拖动/恢复、A 延迟后切 B、当前曲目删除、失败保留歌曲。基础媒体测试静音；后台播放测试音量为 0.1%，避免 WebKit 暂停隐藏窗口中的静音媒体。验证播放状态，不声称做过听感检查。
- 新增打包验证：关闭窗口后保留 WebView、后台音频时间继续推进、页面重载恢复随机播放、应用正常退出。
- 最终普通安装包内，通过原生窗口实测真实视频搜索、分 P 展开、混合流在线播放、跳至约 24 分钟后继续播放及暂停；未向正式歌单写入测试歌曲。
- 打包测试复现：安装 FFmpeg，关闭当前拾音后执行 `./scripts/smoke.sh`；使用临时数据库与测试媒体，不修改正式歌单。
- [打包测试结果](docs/verification/packaged-smoke.json)。测试专用 API/媒体传输仅在 `-tags=smoke` 构建中启用，正常安装包不含模拟实现。
- 访客 API 测试可用 `SHIYIN_LIVE_TEST=1 go test ./internal/music -run TestGuestAPIs -v -count=1`；投稿受限时完整测试预期报错，不能把它记录为全通过。

尚未验证所有合集形态、所有账号/媒体、长时间播放、Intel Mac、性能对比或公证发布。此版本为本机 Apple Silicon 可运行初版，使用 ad-hoc 签名，不是经过 Apple 公证的发行版。

实现规则与文件职责见 [实施记录](docs/implementation.md)。
